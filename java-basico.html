Tu primer programa

Un programa es una lista de instrucciones que la computadora sigue en orden, de arriba hacia abajo. Este es el programa más pequeño que se puede escribir en Java: solo muestra un saludo. Toca cada pieza para saber qué hace.

Toca una pieza del código.

De texto a programa, en tres pasos

1Escribes

El código va en un archivo que se llama igual que la clase: Main.java.

2Compilas

Java revisa que todo esté bien escrito y lo traduce a algo que la computadora entiende. Si falta un ; o una llave, aquí te detiene.

3Ejecutas

Ahora sí corre, instrucción por instrucción, empezando por main.

En NetBeans, IntelliJ o VS Code los pasos 2 y 3 pasan juntos cuando le picas al botón ▶. Pero siguen siendo dos momentos distintos, y saberlo te ayuda a entender qué tipo de error tienes:

«No compila»

El código está mal escrito: falta un punto y coma, un paréntesis, un return… El programa ni siquiera arranca. El editor lo marca en rojo antes de correrlo.

Error al ejecutar

El código está bien escrito y arranca, pero algo sale mal mientras corre: pedir una posición que no existe o, el que más vas a ver en este tema, StackOverflowError. A estos errores Java los llama excepciones, y el programa se detiene en ese momento.

Tres reglas que Java no perdona
  • Distingue mayúsculas de minúsculas. Main, main y MAIN son tres cosas diferentes.
  • Cada instrucción termina en ;. Los renglones que abren un bloque con { no lo llevan.
  • Todo lo que abres, lo cierras: cada { con su } y cada ( con su ).

Un detalle más: todo lo que va después de // en un renglón es un comentario. Java lo ignora; sirve para dejar notas a quien lee el código. Vas a ver muchos en esta página.

Variables y tipos de datos

Una variable es una cajita con nombre donde guardas un dato para usarlo después. En Java cada caja tiene un tipo, y solo le cabe ese tipo de dato: en una caja de enteros no puedes guardar texto.

intel tipo edadel nombre =guarda 20el valor ;fin

Se lee: «crea una caja para enteros que se llame edad y guárdale un 20». Después se usa solo con su nombre, y se le puede cambiar el valor sin volver a escribir el tipo:

int edad = 20;           // se crea con un valor
edad = 21;               // se cambia: ya no lleva int
int en10 = edad + 10;    // se usa: en10 vale 31

Los tipos que vas a usar

En Java, = no significa «igual»

= significa guarda: calcula lo de la derecha y lo mete en la caja de la izquierda. Por eso edad = edad + 1; tiene sentido: «guarda en edad lo que vale edad, más 1». Para preguntar si dos cosas son iguales se usan dos signos: ==.

Un detalle de este sitio: en las explicaciones vas a leer cosas como «con n = 3». Eso es español, no Java: significa «cuando n vale 3».

3

Operadores

Los de siempre funcionan como en la calculadora: + suma, - resta y * multiplica. Los que tienen truco son la división y el módulo, y son justo los que más usa la recursividad con números.

/ entre enteros tira los decimales

Si los dos números son int, el resultado también lo es: 7 / 2 da 3, no 3.5. No redondea: corta. Para tener decimales, al menos uno debe ser double: 7.0 / 2 da 3.5.

% da el residuo

El módulo es lo que sobra de una división entera: 7 % 2 da 1, porque 7 = 2 × 3 + 1. Sirve para saber si un número es par (n % 2 == 0) o para sacar su último dígito (n % 10).

El + con texto, y quién va primero

Si de algún lado del + hay texto (un String), el + ya no suma: pega. "ida " + 3 da "ida 3", y así se imprime una variable con un mensaje. Java lee de izquierda a derecha, y eso cambia el resultado: 1 + 2 + "x" da "3x" (primero suma, luego pega), pero "x" + 1 + 2 da "x12" (desde el principio ya hay texto).

Y como en la primaria, *, / y % van antes que + y -: 2 + 3 * 4 da 14, no 20. Los paréntesis cambian el orden: (2 + 3) * 4 da 20.

Pruébalo: la división de la primaria

Escribe dos enteros. Es la misma división que hacías a mano: / te da el cociente y % el residuo.

Decisiones y ciclos

Hasta aquí todo corre de arriba hacia abajo, una vez. Con if el programa decide qué camino tomar, y con los ciclos repite.

if / else: tomar una decisión

if (calificacion >= 8) {
    System.out.println("Aprobaste");
} else {
    System.out.println("A estudiar");
}

Entre los paréntesis va una condición. Si da true, se ejecuta el primer bloque; si da false, el del else. El else es opcional: sin él, cuando la condición es falsa no pasa nada y el programa sigue con lo de abajo.

Si el bloque tiene una sola instrucción, las llaves se pueden quitar. Esta forma corta la vas a ver mucho en recursividad:

if (n == 0) return 1;    // lo mismo que con llaves, en un renglón
Un return termina el método en ese instante

En cuanto Java llega a un return, el método se acaba ahí mismo, aunque haya más código abajo. Por eso if (n == 0) return 1; funciona como una puerta de salida: si n vale 0, lo de abajo ya no se ejecuta. Eso es exactamente un caso base, como vas a ver en la siguiente parte.

for y while: repetir

for · cuando sabes cuántas vueltas

for (int i = 1; i <= 3; i++) {
    System.out.println(i);
}

Imprime 1, 2 y 3. Entre los paréntesis hay tres partes separadas por ;: desde dónde empieza (int i = 1), mientras qué se repite (i <= 3) y cómo avanza (i++, que significa «súmale 1 a i»).

while · mientras se cumpla algo

int n = 3;
while (n > 0) {
    System.out.println(n);
    n = n - 1;
}

Imprime 3, 2 y 1. Repite mientras la condición sea verdadera. Si se te olvida cambiar n, la condición nunca se vuelve falsa y se queda repitiendo para siempre: un ciclo infinito.

¿Por qué ver ciclos si el tema es recursividad? Porque todo lo que hace una recursión se puede hacer también con un ciclo, y es pregunta de examen. Los comparamos en la siguiente parte.

Métodos: el corazón de todo

Un método es un pedazo de código con nombre que hace una tarea. Lo escribes una vez y lo usas cuantas veces quieras. Si esto te queda claro, ya llevas la mitad de la recursividad: un método recursivo es simplemente un método que se usa a sí mismo.

Piensa en una licuadora: le metes ingredientes (los parámetros), hace su trabajo (el cuerpo) y te entrega un licuado (lo que devuelve). Para usarla no necesitas saber cómo funciona el motor.

Al primer renglón de un método se le llama su firma: dice quién puede usarlo, qué devuelve, cómo se llama y qué recibe. Toca cada pieza de este método:

Toca una pieza del método.

¿Dónde se escribe un método?

Dentro de la clase, pero fuera de main. Los métodos son hermanos de main, no van adentro de él. El orden entre ellos no importa.

public class Main {

    // tus métodos van aquí: dentro de la clase, fuera de main
    public static int sumar(int a, int b) {
        int resultado = a + b;
        return resultado;
    }

    public static void main(String[] args) {
        int total = sumar(2, 3);
        System.out.println(total);
    }
}

Qué pasa cuando llamas a un método

Fíjate en int total = sumar(2, 3);. Llamar a un método es escribir su nombre con los datos entre paréntesis. Esto es lo que hace Java, en orden:

  1. Deja main en pausa, justo en ese renglón.
  2. Copia los valores que mandaste a los parámetros: a vale 2 y b vale 3.
  3. Ejecuta el cuerpo de sumar: resultado vale 5.
  4. Llega a return resultado;: sumar termina y devuelve un 5.
  5. main sigue donde se quedó, y la llamada sumar(2, 3) se reemplaza por el 5 que devolvió. Es como si dijera int total = 5;
Parámetro vs argumento

Parámetro es la variable que aparece en la firma: a y b. Argumento es el valor concreto que mandas al llamar: 2 y 3. Los parámetros son las cajas; los argumentos, lo que metes en ellas. Y cada vez que se llama al método se crean cajas nuevas, solo para esa llamada, con los argumentos que mandaste. Esto es clave para la recursividad.

La trampa clásica: imprimir no es devolver

return · le devuelve el valor a quien llamó

public static int doble(int x) {
    return x * 2;
}

// en main:
int r = doble(4) + 1;    // r vale 9

El 8 regresa a quien llamó, y se puede seguir usando en otras cuentas.

println · solo lo muestra

public static void dobleImprime(int x) {
    System.out.println(x * 2);
}

// en main:
dobleImprime(4);    // se ve un 8, y ya

El 8 se ve en pantalla, pero nadie lo recibe: el método es void. Escribir dobleImprime(4) + 1 ni siquiera compila.

Esto es clave en recursividad: cada llamada necesita el valor que le devuelve la siguiente para armar su propio resultado. Si solo se imprime, a la llamada que espera no le llega nada.

Arreglos y String

Dos formas de guardar varios datos en orden. Aparecen en varios ejemplos recursivos, así que vale la pena tenerlas claras.

Arreglos: varias cajas en fila

int[] numeros = {4, 8, 15, 16, 23, 42};
4081152 163234425

arriba el valor · abajo su posición

  • int[] significa «arreglo de enteros». Los valores van entre llaves, separados por coma.
  • Cada elemento tiene una posición (su índice) que empieza en 0, no en 1: numeros[0] es 4 y numeros[2] es 15.
  • numeros.length dice cuántos elementos hay: 6. Va sin paréntesis.
  • Como se empieza a contar en 0, el último está en la posición numeros.length - 1, o sea 5. Pedir numeros[6] truena al ejecutar con ArrayIndexOutOfBoundsException.

String: una fila de caracteres

A un String también se le dice cadena (de caracteres). Funciona parecido a un arreglo: cada carácter tiene su posición, empezando en 0. La diferencia es que se consulta con métodos, que llevan paréntesis. Escribe una palabra, mueve la posición y mira qué da cada uno:

Dos detalles que confunden a todos
  • En un arreglo es arr.length, sin paréntesis. En un String es s.length(), con paréntesis.
  • Para comparar dos String no uses ==: usa s.equals("hola"). El == revisa si son el mismo objeto en memoria, no si dicen lo mismo, y a veces falla sin avisar.

Una llamada espera a la otra

Lo último, y lo más importante para lo que sigue. Un método puede llamar a otro, que a su vez llama a otro… Y cada vez, el que llama se queda en pausa hasta que el llamado termina y le devuelve su resultado.

Avanza este programa paso a paso. Cada tarjeta de la columna «Llamadas en curso» es una llamada que no ha terminado, con sus propias variables (un mismo método puede tener varias tarjetas a la vez). La de hasta arriba es la que se ejecuta ahorita; las de abajo están esperando. En la parte 3 vas a ver que esta columna se llama pila de llamadas y que a cada tarjeta se le dice marco.

Fíjate en esto antes de seguir

La x de doble y la x de cuadruple se llaman igual, pero no son la misma caja: cada llamada tiene las suyas. Y cuando doble termina, su tarjeta desaparece y cuadruple sigue exactamente donde se había quedado. La recursividad funciona igualito; la única diferencia es que el método que llama y el llamado son el mismo.
