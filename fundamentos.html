REST en 6 reglas

REST = REpresentational State Transfer. No es un lenguaje ni una librería: es un estilo de diseñar APIs. Si cumple estas reglas, es RESTful.

La que más cae

Sin estado (stateless). Cada petición viaja completa y el servidor no recuerda la anterior. Si necesitas identidad, la mandas en cada petición.

Los métodos HTTP

La URL dice qué recurso. El método dice qué le haces. Con estos cinco cubres todo el examen.

La trampa clásica: PUT vs PATCH

PUT · reemplazo total

Mandas el objeto completo. Lo que no mandes se pierde.

PUT /v1/mascotas/42
{ "nombre": "Firulais", "edad": 4, "especie": "perro" }

PATCH · cambio parcial

Mandas solo lo que cambia. Lo demás queda igual.

PATCH /v1/mascotas/42
{ "edad": 5 }
Dos palabras que suenan a examen

Seguro (safe): no modifica nada. Solo GET.
Idempotente: repetirlo 100 veces deja lo mismo que hacerlo 1 vez. GET, PUT y DELETE sí. POST no — lo repites y creas 100 registros.
