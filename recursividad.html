1

La idea en una frase

La respuesta corta, la que sirve en cualquier examen: un método es recursivo cuando se llama a sí mismo para resolver una versión más pequeña del mismo problema.

¿Un método que se usa a sí mismo? Suena a truco, pero es una forma de pensar que ya usas. Así se come una bolsa de papitas: te comes una papita y luego te comes el resto de la bolsa. «El resto de la bolsa» es el mismo problema de antes, solo que con una papita menos. ¿Y cuándo paras? Cuando la bolsa ya está vacía.

Las muñecas rusas

Abres una muñeca y adentro hay otra igual, pero más chica. La abres y hay otra más chica. Hasta que llegas a una tan pequeña que ya no se abre: ahí terminas. Esa última muñeca es el caso base.

Dos espejos de frente

Ves un reflejo dentro de otro reflejo, dentro de otro… y nunca termina. Eso es una recursión sin caso base: en Java, en vez de un pasillo infinito, obtienes un error.

El diccionario

Buscas una palabra y la definición usa otra palabra que no conoces, así que la buscas también. Terminas cuando llegas a una definición que ya entiendes.

Frase para el examen

«La recursividad es una técnica en la que un método se llama a sí mismo para resolver un problema, dividiéndolo en versiones más pequeñas del mismo problema hasta llegar a un caso base que se resuelve directamente.»

2

La fila del cine

La analogía que mejor explica cómo corre una recursión. Avanza paso a paso y fíjate en dos cosas: las preguntas viajan hacia adelante y las respuestas regresan hacia atrás.

3

Las dos partes que siempre lleva

En la fila del cine ya viste las dos. Todo método recursivo, sin excepción, las tiene:

Caso base · la condición de paro

El caso tan pequeño que la respuesta se sabe sin hacer más llamadas. Es la persona de la fila 1. Es lo que hace que la recursión termine, y se revisa antes de la llamada recursiva.

Caso recursivo · el que se llama a sí mismo

Para todos los demás casos: el método se llama con un problema un poquito más pequeño y usa lo que le devuelven para armar su respuesta. Es preguntarle al de adelante y sumarle 1.

Léelo como si fuera español

«La suma hasta n es: si n es 0, cero. Si no, n más la suma hasta n − 1.» Con n = 3 queda así:

suma(3) = 3 + suma(2)
        = 3 + (2 + suma(1))
        = 3 + (2 + (1 + suma(0)))
        = 3 + (2 + (1 + 0))       ← caso base: aquí se deja de llamar
        = 6

Nadie calculó la suma «de golpe»: cada llamada dejó una cuenta pendiente y todas se resolvieron de regreso. En la parte 3 vas a ver esto moverse, paso a paso.

4

Las 3 reglas de oro

Si un método recursivo rompe alguna de estas tres, no funciona: úsalas como checklist cada vez que escribas uno. Y aunque las cumpla todas, revisa que el caso base devuelva el valor correcto: un factorial que devuelve 0 en su caso base cumple las tres reglas y aun así siempre da 0.

El salto de fe

Al escribir un método recursivo no intentes seguir todas las llamadas en tu cabeza: te vas a marear. Haz como la gente del cine: confía en que la llamada con el problema más pequeño te devuelve la respuesta correcta, y preocúpate solo por usarla bien. Es la misma confianza que le tienes a System.out.println: lo usas sin saber cómo está hecho por dentro.

5

Cómo pensar un método recursivo

Cuando te pidan escribir uno desde cero, sigue estos cuatro pasos. Vamos a aplicarlos a un problema nuevo: calcular base elevado a exp sin usar Math.pow, el método que Java ya trae para potencias. Por ejemplo, 2⁵ = 32.

  1. 1
    Encuentra el caso más fácil.

    ¿Con qué valor la respuesta es obvia, sin calcular nada? Cualquier número elevado a la 0 vale 1. Ese es el caso base: si exp == 0, devuelve 1.

  2. 2
    Imagina que ya tienes resuelto el problema un poquito más chico.

    No lo calcules: supón que alguien ya te dio la respuesta de potencia(base, exp - 1). Si quieres 2⁵, imagina que ya te dijeron que 2⁴ = 16.

  3. 3
    Úsalo para resolver el tuyo.

    Con 2⁴ = 16 en la mano, 2⁵ es 2 × 16 = 32. En general: base * potencia(base, exp - 1). Ese es el caso recursivo.

  4. 4
    Revisa que siempre llegues al caso base.

    exp baja de uno en uno: 5, 4, 3, 2, 1, 0. Sí llega. Prueba también el caso más raro: con exp = 0 devuelve 1 de inmediato, bien. Con un exponente negativo nunca llegaría a 0; si eso puede pasar, hay que validarlo.

Y el método sale solo:

public static int potencia(int base, int exp) {
    // paso 1: el caso más fácil
    if (exp == 0) {
        return 1;
    }
    // pasos 2 y 3: confía en el problema más chico y úsalo
    return base * potencia(base, exp - 1);
}

Tipos de recursión

Vocabulario que cae en los exámenes. Van en parejas, porque cada tipo se entiende mejor junto a su opuesto.

Dato que suma puntos

Algunos lenguajes convierten la recursión de cola en un ciclo para no gastar memoria. Java no lo hace: aunque la escribas de cola, cada llamada sigue ocupando su lugar en la pila.

8

Recursión vs ciclos

Todo lo que se hace con recursión se puede hacer también con un ciclo (for o while), y al revés. Este es el mismo factorial de las dos formas:

Con un ciclo (iterativo)

public static long factorialCiclo(int n) {
    long resultado = 1;
    for (int i = 2; i <= n; i++) {
        resultado = resultado * i;
    }
    return resultado;
}

Una variable va acumulando la multiplicación, vuelta por vuelta.

Recursivo

public static long factorial(int n) {
    if (n == 0) {
        return 1;
    }
    return n * factorial(n - 1);
}

No hay acumulador: cada llamada deja pendiente su multiplicación y todas se resuelven de regreso.

Frase para el examen

«Todo algoritmo recursivo tiene una versión iterativa. La recursión da un código más corto y claro cuando el problema se divide en subproblemas del mismo tipo, a cambio de usar más memoria, porque cada llamada ocupa un espacio en la pila de llamadas.»
