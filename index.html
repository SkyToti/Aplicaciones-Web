🍽️ ¿Qué es una API?

La respuesta corta que sirve en cualquier examen: una API es un contrato que le dice a un programa cómo pedirle cosas a otro programa. Ni más ni menos.

El estilo de arquitectura

📜 REST en 6 reglas

REST = REpresentational State Transfer. No es un protocolo ni una librería: es un estilo de diseñar APIs. Si cumple estas reglas, es RESTful.

⚠️ La que más cae en el examen: Sin estado (stateless). Cada petición viaja completa y el servidor no recuerda la anterior. Si necesitas identidad, la mandas en cada petición (por ejemplo, un token).

Los verbos

⚡ Métodos HTTP

La URL dice qué recurso, el método dice qué le haces. Con estos 5 cubres el 100 % del examen.

🎯 La trampa clásica: PUT vs PATCH

PUT = reemplazo total

Mandas el objeto completo. Lo que no mandes, se borra o se va a su valor por defecto.

PUT /mascotas/42
{ "nombre": "Firulais", "edad": 4, "especie": "perro" }

PATCH = cambio parcial

Mandas solo los campos que cambian. Lo demás queda igual.

PATCH /mascotas/42
{ "edad": 5 }
Dos palabras que suenan a examen:
Seguro (safe): no modifica nada. Solo GET.
Idempotente: repetirlo 100 veces da el mismo resultado que hacerlo 1 vez. GET, PUT y DELETE lo son. POST no (lo repites y creas 100 registros).
